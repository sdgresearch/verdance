# Decisions

- 2026-11-25 · Evaluate null park distances as `meets_300 = False` in `Merge` when `cfg.osm.fetch_buffer >= 300` via `evaluate_rule(..., null_distance_fails=...)` · Alternatives: (a) keep null distances excluded from `pct_meets_300` (inflated compliance whenever unreachable buildings existed); (b) replace `NaN` with `inf` in `t300.py` (breaks existing `test_t300_distances.py` contract) · Reason: preserves `t300.py` and standalone `evaluate_rule()` backwards compatibility while preventing unreachable/far-from-park buildings from inflating `pct_meets_300`.
- 2026-11-25 · Default `load_tables(..., load_buildings_gdf=False)` so `tables["buildings_gdf"]` is `None` unless requested · Alternatives: (a) keep loading the full buildings GeoDataFrame on every run; (b) drop the key from the returned dict · Reason: `buildings_gdf` was unused across `src/` and `tests/` and wasted ~1 GB RAM on country-scale runs, while keeping the key avoids breaking external dict-shape expectations.
- 2026-11-25 · Support `visibility.facade_offset == 0.0` and `visibility.end_skip == 0.0` mathematically in `observers.py`, `los.py`, and `vector_engine.py` · Alternatives: reject `0` in `config/loader.py` · Reason: `0` is a valid boundary setting in existing configs and docs; fixing self-hit filtering and the `t -> 1` limit avoids breaking configs while removing `ZeroDivisionError` and dropped observers.
- 2026-11-25 · Anchor `[tool.hatch.build.targets.sdist]` `include` entries with leading `/` in `pyproject.toml` · Alternatives: add `exclude` globs for `*-venv` · Reason: unanchored includes matched nested directories such as `netcheck-venv/**/tests/` and `LICENSE`; root-anchoring guarantees only tracked project paths enter sdists regardless of local untracked directories.
- 2026-11-25 · Leave `gdal==3.10.0` in `[dependency-groups] dev` untouched for now · Alternatives: remove it from `pyproject.toml` immediately · Reason: removing it without running `uv lock` would desync `uv.lock` and break `uv sync --frozen`; deferred to a dedicated dependency/lockfile update.
- 2026-11-26 · Push `v*` release tags to `upstream` (`sdgresearch/verdance`) as the one documented exception to the `origin`-only rule · Alternatives: (a) keep the rule absolute and cut releases by creating the tag through the GitHub UI on `sdgresearch/verdance`; (b) move the release workflow and the PyPI Trusted Publisher to the fork · Reason: the workflow and the Trusted Publisher are scoped to `sdgresearch/verdance`, so a tag pushed to the fork publishes nothing; the UI route works but leaves the tag out of the fork's history, and relocating the publisher would make the fork the release origin.
